# QA Test & Auto-Fix Skill

このSkillは、GTA5メカニック計算機（`gta5-mechanic-calculator`）の全機能・全画面に対して網羅的なQAテストを実行し、検出されたバグや不具合を自律的かつ安全に修正・再検証するプロトコルを定めます。

## いつこのSkillを使用するか
- 「QAテストを実行して」「バグを修正して」「全画面の動作確認をして」「テストして直して」等の指示を受けた時
- コード変更・新機能追加・リファクタリング後のリグレッションテストおよび品質担保
- CI/CDパイプライン失敗時の原因究明と自動修復

---

## ワークフロー手順

### ステップ 1: テスト環境の確認と準備
1. Node.js依存関係がインストールされているか確認（未導入の場合は `npm install` を実行）。
2. 必要に応じてPlaywrightのブラウザバイナリを確認（初回のみ `npx playwright install chromium`）。

### ステップ 2: テストの実行
以下のコマンドでテストスイートを実行します。

```bash
# 全体テスト（単体テスト ＋ E2Eテスト）
npm test

# 単体テストのみ（計算ロジック・共通関数）
npm run test:unit

# E2Eテストのみ（全ページロード・DOM操作・コンソールエラー監視）
npm run test:e2e
```

### ステップ 3: テスト結果の解析（失敗時）
テストが失敗した場合、以下の情報を収集・分析します。
1. **失敗したテスト種別**: 単体テスト（ロジック不一致）か E2Eテスト（コンソールエラー / DOMセレクタ不一致 / 描画崩れ）か
2. **スタックトレースとエラーメッセージ**: 例外箇所、行番号、期待値と実際の値の差分
3. **影響範囲**: 単一ファイルで完結するか、マスター設定（`firebase-config.js`）や共通関数（`common.js`）に起因するか

### ステップ 4: 安全ガード付き自律修正（Auto-Fix ループ）
- **最大試行回数**: 最大3回まで「修正 ➔ テスト再実行」のループを繰り返す。
- **自動修正対象**:
  - 計算ロジックの不一致（税率・割引計算・合計加算のミス等）
  - JavaScriptの構文エラー・未定義変数・タイポ
  - DOM要素のID/class名変更に伴うイベントリスナーや参照の不整合
  - エスケープ処理（XSS脆弱性）やフォーマットの漏れ
- **ユーザー確認が必要なケース（中断して相談）**:
  - 仕様そのものが曖昧・矛盾している場合
  - 大規模なUI再構築や破壊的変更が必要な場合

### ステップ 5: パス確認と完了報告
全テストがパスしたら、以下のフォーマットでユーザーに報告します。

```markdown
## QAテスト & 自動修正 完了レポート

### 実行結果サマリー
- 単体テスト: X件パス / 0件失敗
- E2Eテスト: Y件パス / 0件失敗

### 検出・修正された不具合（該当する場合）
- **[ファイル名:行番号]**: 不具合の概要と修正内容
  - 原因: ...
  - 修正: ...

### 動作確認状況
全画面（修理・カスタム・買取・レジ・設定）の画面ロード、コンソールエラーゼロ、計算整合性を検証完了。
```
