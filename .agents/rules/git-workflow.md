# Git運用・自動化ルール

## 1. 操作の自動実行と確認基準
- **確認なしで自動実行する操作**:
  - `git add`
  - `git commit`
  - `git push`（通常プッシュ）
  - `git checkout` / `git switch`
  - `git pull` / `git fetch`
  - `git status` / `git diff` / `git log`
- **必ず事前にユーザー確認を行う破壊的操作**:
  - `git reset --hard`
  - `git push --force` (`-f`)
  - `git branch -D`（未マージブランチの強制削除）
  - その他、作業内容や履歴を不可逆的に破棄する恐れのある操作

## 2. 実行タイミング
- タスクや機能実装が完了し、動作確認・検証が取れたタイミングで、自律的にコミットおよびリモートへのプッシュを実行する。
- ユーザーからの明示的な指示を待つ必要はない。

## 3. コミットメッセージ規約
- **フォーマット**: Conventional Commits（日本語）
  - 形式: `<type>(<scope>): <日本語の説明>` または `<type>: <日本語の説明>`
  - タイプ例:
    - `feat`: 新機能の追加
    - `fix`: 不具合の修正
    - `refactor`: リファクタリング
    - `style`: コードスタイルや見た目の調整
    - `docs`: ドキュメントの変更
    - `chore`: 設定やビルド周りの細かな変更
  - 例:
    - `feat: 設定画面のタブ切り替え改善`
    - `fix: 修理計算の消費税端数処理を修正`
