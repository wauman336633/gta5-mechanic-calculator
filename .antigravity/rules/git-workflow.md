# GitHub運用ルール

当リポジトリにおけるGitおよびGitHubの運用規約です。AIアシスタントおよび開発者は以下のルールを厳格に遵守してください。

## 1. ブランチ運用の基本原則
- **`main` ブランチへの直接変更は禁止**:
  - `main` ブランチは公開（本番）環境です。
  - `main` ブランチへの直接コミット・直接プッシュは一切行わないでください。
- **作業ブランチの作成タイミング**:
  - 要件定義・設計方針の合意後、実装作業を開始するタイミングで最新の `main`（`git checkout main` → `git pull origin main`）から作業ブランチを作成してください。
- **ブランチ命名規則**:
  - フォーマット: `<type>/<kebab-case-description>`
  - プレフィックス一覧:
    - `feature/`: 新機能追加・機能改善
    - `fix/`: バグ修正
    - `refactor/`: リファクタリング
    - `chore/`: 設定変更・ツール更新・雑務
    - `docs/`: ドキュメント修正
  - 例: `feature/feedback-system`, `fix/dynamic-price-labels`, `chore/setup-git-workflow-rules`

## 2. コミット規約
- コミットメッセージは**日本語**で記述してください。
- 形式例:
  - `feat: フィードバック送信フォームの実装`
  - `fix: 価格計算ロジックの端数処理を修正`
  - `chore: GitHub運用ルールの追加`

## 3. プルリクエスト（PR）の作成
- 作業完了後、速やかにリモートブランチへプッシュし、GitHub CLI（`gh pr create`）を使用して `main` ブランチ宛てのプルリクエストを自動作成してください。
- PRタイトルおよび本文は**日本語**で記述してください。
- PR本文には以下の構成を含めてください:
  ```markdown
  ## 概要
  （作業目的や背景の簡潔な説明）

  ## 変更点
  - 変更項目1
  - 変更項目2

  ## 確認内容
  - 実施したテストや動作確認の内容
  ```
- PR作成完了後、PRのURLをユーザーに提示してください。
